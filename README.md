# 旅策 · 把计划装进口袋

手机优先的旅行规划工具，源自中文手机端原型。浅色森林绿界面，无需安装 App 即可体验。

## 已实现

- 多份旅行计划：日期、同行人、人均预算与偏好；杭州、成都、大理提供本地灵感模板，其他城市从空白创建。
- AI 行程：统一 DeepSeek 后端，按出行条件生成 1–7 天行程；先预览再保存为新旅行，支持取消与错误反馈，不覆盖已有计划或账单。
- 每日行程：添加、编辑、删除地点，上下排序，预计费用与停留时间。
- 地图：路线示意及高德地点查询外链（非真实点位、非导航引擎）。
- 旅行账本：消费增删改、付款人与参与人、按整数分均摊、尾差处理、转账结算建议。
- 出发清单：分类、增删、勾选、进度与预设去重。
- 我的：切换旅行、修改名称与预算、食宿收藏、JSON 备份与追加导入、当前日程打印。
- 只读快照链接：仅含地点、时间、类型与停留时间，不含成员姓名、私人备注与账单。
- 本机自动保存；存储失败提示并保留导出入口。

## 运行与检查

需要 Node.js 22.13 或以上（测试使用内置 SQLite），不需要安装 npm 依赖。

```sh
npm run dev
# 打开 http://localhost:3000
npm test
npm run build
```

源码直接位于 `dist/`，可部署到任何静态托管平台。`scripts/serve.mjs` 仅供本地开发；部署时使用正式静态托管。

## GitHub Pages 部署

仓库内已配置 `.github/workflows/pages.yml`：推送至 `main` 后，自动运行测试、检查静态资源，并只发布 `dist/`，不会发布源码、测试或托管配置。

首次启用：仓库 **Settings → Pages → Build and deployment → Source → GitHub Actions**。之后到 **Actions → Deploy GitHub Pages → Run workflow** 发起第一次部署；后续推送会自动更新。最终访问地址以该工作流的 `github-pages` environment 链接为准。

GitHub Free 需要公开仓库才能使用 Pages；私有仓库需要支持该功能的付费计划。Pages 网站公开访问，不要求登录 ChatGPT。不同域名的浏览器存储互不相通，从其他体验地址迁移时，可先导出 JSON 备份再在新地址导入。

## 数据说明

数据保存在当前浏览器的 `localStorage`，不上传账单，不自动跨设备同步。初始杭州行程与消费为可修改的示例。新建旅行不会继承示例账单。

完整备份包含同行人和消费明细，请妥善保管。导入前校验格式与成员关联，只追加尚不存在的旅行，不覆盖同 ID 的本机内容。

分享内容打包在 URL fragment 中，是生成时的快照。修改原计划不会同步，已分享快照无法远程撤回；接收者需要具有托管站点访问权限。不要在公开地点名称中填写隐私信息。

普通新建旅行可使用本地模板；「AI 规划」调用统一的 DeepSeek 服务。两者都不提供实时天气、票价、营业时间与精确交通时长。行程预计费用不会自动计入实际消费，出发前请自行核实。

## AI 服务接入状态

AI 生成表单、取消、严格结果校验和草稿预览已实现。统一后端正在迁移至独立部署平台，前端当前没有配置调用地址；服务未就绪时会明确显示不可用，不把本地模板作为 AI 结果返回。原有手动规划和模板功能不受影响。

`dist/ai-api.js` 中的 `AI_BASE` 只能配置已验证的后端 origin，不得包含 API Key。普通用户不填写密钥，后端通过固定 DeepSeek 地址调用模型。API Key 不应提交到 GitHub，也不应放进前端、备份或分享链接。

AI 请求只包含目的地、日期、人数、人均预算、节奏、偏好和用户填写的补充要求，不发送同行人姓名和已有账单。不要在补充要求中填写敏感个人信息。生成成功后先预览，再另存为新旅行，已有行程不被覆盖。

原实验后端位于 `backend/`，尚需适配新的独立托管平台，不应将该目录直接部署到 GitHub Pages。前端发布工作流只上传 `dist/`。实际 AI 生成需完成后端部署并配置有效且有余额的 DeepSeek Key。自动化测试使用固定响应，不消耗实际模型用量。
