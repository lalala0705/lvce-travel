# 旅策 PRD

版本：0.4（2026-11-24）

本文维护确认后的需求、边界和验收状态，不逐字保存聊天。早期 Figma 原型用于视觉参考，后续实现与规则以本文件为准。

## 产品目标与信息架构

手机优先的旅行工具，支持从“还不知道去哪儿”到明确日程，以及旅行中的临时调整。

主导航：行程、问 AI、美食·住宿、记账、清单、我的。删除首页“把时间留给风景，把计划交给旅策”宣传横幅：品牌说明已由顶部标识承担，首屏优先呈现日程与可操作的地图。

- 行程：日程编辑、实际地图、道路线路、合理性校验。
- 问 AI：原 AI 规划与游玩灵感合并为一个页面，支持新旅行和已有旅行当天调整。
- 美食·住宿：高德真实地点与官方平台查询入口，替代重复的独立地图板块。
- 记账、清单、我的：保留原能力及本机数据，不因界面改版清空。

## 交付与验证状态

原有统一 DeepSeek 生成、高德真实底图、POI 搜索、坐标转换、步行/驾车接口已在公网验证。

本轮新增对话后端、调整预览、全程/单日地图和路线校验。代码及本地流程验证与线上接通分别记录：前端通过 GitHub Pages 发布；新的 `/api/chat` 和 AI 次数策略须在腾讯云升级后端后生效。在升级前，条件生成草稿仍走原接口，对话入口明确显示待升级，不冒充已连接。

大众点评、同程、携程：用户确认本轮保留待接入；没有官方接入文档或授权凭证，不部署非官方浏览器抓取服务，不把官网链接当作 MCP。公开资料中查到的[同程商旅](https://tmc.ly.com/zh/resources/updates/open-mcp-skills-cli)与[携程商旅](https://ct.ctrip.com/thinktanks/235566117077549)合作能力不能直接等同于本项目已获准调用消费者餐饮评价、酒店房价和库存。

## 问 AI：统一沟通与规划

### 新旅行

1. 用户从一句话或快捷主题开始（附近玩水、轻松徒步、带娃半日游），不强制先确定目的地。
2. 每次最多追问 1–2 个缺失条件，可逐步明确城市、日期、天数、人数、预算、偏好和体力/交通约束；默认出行条件可展开修改。
3. 搜索意图由后端向高德查询，最多展示 3 个真实候选；模型不得直接提供伪造的候选 POI。选中候选后可围绕它继续沟通。
4. 按用户要求生成 1–7 天草稿，严格校验日期、天数、时间重叠、项目类型与金额；先预览，确认后保存为新旅行。
5. 路线车程、天气、开放和安全限制未查证时不得宣称已满足。当前对话不自动读取精确定位，城市搜索不等同于“开车一小时内”。授权定位仍在行程地点搜索中单独操作。

### 旅行中调整

1. 在行程当天或路线校验页点击「问 AI 调整」，进入同一页面的调整模式；可选定要调整的那一天。
2. 用户说明已完成的活动及变化（下雨、体力、晚出门等）。不推测旅行进度；信息不足时先追问。
3. 生成一天的调整草稿，展示新增、移除及时间变更，未确认前不修改当前行程。
4. 确认时只替换选中的一天；其他天、成员、预算、账单、清单、收藏保留。保留同名地点已有的 POI 与私人备注。
5. 检查生成前后当天数据签名；如果用户在等待期间改过当天内容，拒绝覆盖，要求重新生成。
6. 不自动将草稿预计费用写入账单，不自动下单或支付。

### 对话数据与调用策略

- 发送本次消息、最多 6 条必要历史、出行条件；调整时发送当天地点名称、时间、类型、停留和预计费用。
- 不自动发送成员姓名、账单、原有私人备注、精确定位或 API Key。用户主动输入的文本会发送给 DeepSeek，输入框旁说明用途，提示不要填密钥等敏感信息。
- 对话保留于当前页面会话，不写入旅行备份或分享链接。
- 根据用户“**不限制**”的明确选择，腾讯云生产入口不设置 AI 每日/每小时调用次数上限；生成与对话均适用。实际用量由 DeepSeek 账户计费，平台自身配额仍适用。
- 防重复 requestId、取消、超时、长度与结果结构校验保留；失败不自动重试。

## 行程地图与道路线路

1. 地图移至行程页，替代示意图；按需加载高德 JS API 2.0，保留高德标识。
2. 可以选择「当天线路」或「整体旅行」，使用「天数-顺序」标记；每日不同颜色，有图例。
3. 只展示已确认的高德 POI。未匹配地点明确提示，可手动搜索匹配；不得自动把首个重名候选认作正确地点。
4. 道路线路按用户选择步行或驾车查询。当天显示相邻地点道路，整体旅行包含跨天相邻地点的转移，跨日道路使用不同样式。
5. 没有道路数据时不画直线冒充道路；不跨过未匹配的中间地点，伪造两端直接相连。
6. 由用户点击「显示道路线路」发起查询，单次最多 24 段，超过时改为按天查看；会话内缓存同坐标、同交通方式结果，不自动重复查询。
7. 城市初始视野来自真实地图地点数据；已有确认 POI 时以这些点位适配视野，不回落到 SDK 默认北京视野冒充行程城市。

### 合理性校验

- 检查活动时间重叠、停留超过当天、重复地点、可能折返。
- 已有道路查询时，对比相邻地点可用时间与道路耗时，另留驾车 10 分钟、步行 5 分钟缓冲。
- 单段驾车超过 4 小时/步行超过 2 小时给出体力和休息提示，不直接判为禁止。
- 折返为按点位直线分布做的粗检，说明推断依据，不当作全局最优路线结论。
- 缺少点位、没有交通耗时或查询失败时标为「待核实」，不能显示全通过。
- 可以先看本地时间校验，再主动「查询交通后复检」；支持进入问 AI 调整，但不自动重排日程。
- 不核验营业时间、门票、预约、天气、停车、临时封路、专业山野轨迹或水域安全。

## 美食·住宿与外部平台

- 支持城市关键词，以及选中日期已确认地点附近 10 公里内搜索。
- 高德按餐饮/住宿分类查询真实 POI，展示名称、地址和地图入口；不把 POI 资料标成点评评分、成交价格或可订库存。
- 可将地点加入当天安排，继续确认时间、类型和预计费用后保存。
- 大众点评、同程、携程仅提供清楚标识的官网查询入口，并保留“数据待接入”状态。
- 以后获得官方 MCP 文档、端点、权限与授权后再接入服务；不得透传个人浏览器 Cookie 或虚构实时结果。

## 地图凭证、定位与用量

JS Key 可供网页加载 SDK，限制域名白名单；JS 安全密钥与 Web 服务 Key 只在腾讯云环境中保存。服务端固定高德目标地址与路径，限制来源、输入、超时和返回体，不提供任意 URL 代理。

定位默认关闭，用户主动点击并授权后才读取。浏览器 WGS-84 坐标先转换为 GCJ-02 再做周边查询，不将精确定位存入旅行、备份或分享。

AI 取消次数限制不改变地图服务保护：REST 每日 1000 次、每 IP 每小时 60 次，SDK 代理每日 2000 次、每 IP 每小时 300 次。实际许可、额度和计费以高德控制台为准。

## 验收重点

- 宣传横幅和重复地图导航移除，新老记录均可读取，6 项导航在手机可操作。
- 多轮对话、真实候选、草稿、放弃、确认、取消和服务待升级状态可区分。
- 当天调整只改变目标一天，原有 3 笔示例账单和 ¥360 结算结果保持，等待期间编辑不会被覆盖。
- 全程/当天范围和交通方式切换正确，点位与道路有明确来源和顺序。
- 路线未知数据不被判通过，真实道路时间不足会提示，校验不自动修改行程。
- 美食/住宿分类真实，三家平台保持未接入，不伪造评分、价格或库存。
- 新后端可复用现有环境文件升级，不要求重新输入密钥；公网问 AI 与次数策略待服务升级后实测。
